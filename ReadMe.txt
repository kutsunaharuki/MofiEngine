----------------------------------------------------------------
■ ゲーム概要
----------------------------------------------------------------

美術館に潜入した悪党が、美術品を盗む「決定的瞬間」をカメラに収めていく3Dステルスアクションゲームです。

プレイヤーは少年となって美術館に潜み、展示品を狙う悪党（大男・ねずみ男）の犯行現場を撮影します。
見つからないように物陰に隠れながら近づき、ファインダーを覗いてズーム・ピントを合わせ、盗む瞬間をシャッターで切り取ります。

  ジャンル　　　　：3D ステルスアクション（撮影）
  プラットフォーム：Windows（DirectX 12）
  開発言語　　　　：C++ / HLSL
  エンジン　　　　：k2EngineLow をベースに自作拡張（描画・撮影・プロファイラなど）
  開発環境　　　　：Visual Studio（v145 ツールセット）/ 3ds Max / Jenkins
  開発人数　　　　：1 人
  開発期間　　　　：2026 年 7 月〜（開発中）

【ゲームの流れ】

  タイトル――> インゲーム ──> リザルト ──A──> タイトル
                    │
                    ├─ 美術館を探索し、物陰に隠れながら悪党に近づく
                    ├─ ファインダーを覗いてズーム・ピントを合わせる
                    └─ 美術品を盗む瞬間を撮影する

■ 操作説明
----------------------------------------------------------------

ゲームパッド（XInput）とキーボードの両方で操作できます。

【ゲーム中】
  操作                          ゲームパッド      キーボード
  ----------------------------------------------------------------
  移動                          左スティック      W / A / S / D
  カメラ操作                    右スティック      ↑ / ↓ / ← / →
  ファインダーを覗く / やめる   Y                 I
  ズームイン                    RB                7
  ズームアウト                  LB                B
  撮影（シャッター）            B                 K
  サウンドオプションを開く      START             Enter
  物陰に隠れる                  ファインダーを覗いたまま物陰の近くで止まる

  ・ピントはオートフォーカスです。画面中央のグリッド内にいる被写体のうち、
    一番中央に近いものに自動で合います。
  ・被写体の顔のまわりに丸が表示され、中央の十字が丸の中に入っていると
    「撮影範囲内」になります。

【メニュー（サウンドオプション）】
  操作                          ゲームパッド      キーボード
  ----------------------------------------------------------------
  項目の選択                    十字キー 上 / 下  テンキー 8 / 2
  音量の変更                    十字キー 左 / 右  テンキー 4 / 6
  決定                          A                 J
  閉じる                        B                 K

【開発用（Debug / Preview ビルドのみ）】
  F1        ：プロファイラ（CPU / GPU 処理時間）の表示・非表示
  1 / 2 / 3 ：ステージエディタのギズモを 移動 / 回転 / スケール に切り替え

■ こだわったところ
----------------------------------------------------------------

【1】本物のカメラのような「撮影体験」

  ・オフスクリーンレンダリングによるファインダー
    ゲームカメラとは別のカメラでシーンをレンダーターゲットに描き、ファインダーの映像として表示しています。
    撮影時はその瞬間の絵を写真として保存します（k2EngineLow/graphics/PhotoCapture）。

  ・被写界深度（DoF）とピント判定
    ピント距離とボケ量の幅をパラメーター化し、被写体までの距離から「ピントが合っているか」を判定します。
    見た目のボケとゲーム上の判定を同じ値で扱うことで、「ボケて見えるのに成功扱い」といったズレを防いでいます。

  ・オートフォーカス
    画面中央のグリッド内で一番中央に近い被写体の顔を選び、顔のまわりにUIを表示。
    十字がマーカーに入っているときだけ撮影成功とすることで「狙って撮る」手応えを出しています。

  ・3人称 ⇔ 1人称の切り替え
    ファインダーを覗いている間だけ 1人称にし、主人公の移動も撮影用の前後左右歩きのステートに切り替わります。

【2】敵 AI：美術品を盗みに行く悪党

  ・経路探索を 3 つの責務に分割

      NavGrid（通れるマスの地図）
        → Pathfinder（A* で道順）
        → PathFollower（次に進む方向）

    「どこへ行くか」を決める処理と「どう行くか」を切り離したので、目的地モード・今後の警戒モードなどで同じ部品を使い回せます。

  ・地図作成の工夫
    置物の AABB を敵の半径ぶん太らせて塞ぐことで、敵が置物にめり込まないようにしています。
    また体の高さの帯に入る物だけを障害物にし、床や天井の物を誤って壁扱いしないようにしています。

  ・目的地モード
    「美術品へ向かう → 盗む」に加えて、確率で寄り道して見回す段階を入れ、行動が単調にならないようにしています。
    盗む時間・寄り道の確率・半径などはすべて敵の種類ごとの JSON で調整できます。

  ・階層構造を持つステージ
    美術館の階・区画・階段を JSON（MuseumLayout.json）で定義し、敵がいる階の美術品だけを候補として渡しています。

【3】調整しやすい開発環境づくり

  ・パラメーターのホットリロード
    移動速度・クールタイム・カメラ・UI 配置などを JSON でデータとして持ち、ゲームを動かしたまま保存するだけで反映されます。
    ImGui から値を変えてそのまま JSON に保存することもできます。

  ・ステージエディタ
    ImGui + ImGuizmo で置物を選択し、数値入力またはギズモで移動・回転・拡縮してJSON に保存できます。
    初期配置は 3ds Max で作ったデータ（tkl）から読み込めます。

  ・JSON 駆動の UI
    UI のレイアウトを JSON で定義し、カラー・スケール・座標・回転のアニメーションをシーケンスで再生できる仕組みを作りました。
    見た目の調整にコードの変更が要りません。

  ・CPU / GPU プロファイラ
    計りたい区間をマクロで囲むだけで処理時間を計測し、ImGui のグラフで表示します。
    GPU は D3D12 のタイムスタンプクエリで計測し、2 フレーム遅れで結果を読み出しています。
    Release ビルドではマクロが空になり、オーバーヘッドはありません。

【4】描画の最適化

  ・視錐台（フラスタム）カリング
    美術館は置物の数が多いため、カメラに映らない置物を描画登録の段階で省いています。
    描画した数はプロファイラに表示され、効果を数値で確認できます。

  ・自作のレンダリングパイプライン
    ディファード（G-Buffer）、ソフトシャドウ、ポイント / スポットライト、ブルーム、被写界深度（DoF）をエンジン側に実装しています。

【5】個人制作での新たな試み

  ・ステートマシンの共通基底（Core/StateMachineBase）を作り、主人公・敵・キャラクター共通の処理を階層化。
    状態の遷移は優先度の高い順に判定する形に統一し、キャラクターが増えても同じ書き方で追加できるようにしています。

  ・Jenkins による CI の導入
    個人制作でも実際の開発現場に近い環境で作ることに挑戦しました。
    push をトリガーに Debug / Release を Docker 上で並列ビルドし、成果物（exe / pdb）を自動アーカイブ、失敗時は Teams に通知します。
    ファイルの追加漏れなど、自分の環境では気づきにくいビルドエラーをすぐに見つけられるようになりました。
